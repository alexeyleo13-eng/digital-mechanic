## 1. Что сделано за 48 часов и что нет

**Работает и показано в видео.** Видео: 2:14, один дубль на стенде, реальное время без ускорения.

- **Сценарий 1. Отклонение → заявка** (M333YK47, ЯМЗ-236М2, проверка S-0005, F08):
  - вердикт, риск и обоснование приоритета;
  - наблюдения, помеченные гипотезы, проверки и нормативы по руководству со ссылками на страницы PDF;
  - ссылка открывает текст страницы;
  - черновик заявки: механик меняет приоритет и отправляет в ТОиР, приходит номер TKT-…
- **Сценарий 2. Вопрос по базе знаний:** момент затяжки крышек коренных подшипников — 421–461 Н·м, РК стр. 41.
- **Противоречие в руководствах:** тепловые зазоры, РЭ стр. 31 против РК стр. 269 и 276. Агент приводит обе формулировки дословно и советует уточнить у специалиста.
- **Сценарий 3. Сбой записи** (P456AT178, S-0003): выводов о двигателе нет, агент просит повторить запись.
- **Режим «Главный механик»:** сводка по парку, история проверок и график anomaly_score.

**Работает, но не показано в видео.** Проверяется на стенде и тестами (`tests/`, `scripts/eval_questions.py`):
- **Запись с помехами (warning):** предупреждение показывается всегда, заявка отправляется только после отметки механика. Пример — O658MX98, S-0063.
- **Порог уверенности 0,50:** ниже порога заявка не оформляется. Пример — M739BA198, S-0103.
- **Тип неисправности не подходит двигателю:** агент сообщает о вероятной ошибке классификации, нормативы не подставляет, заявку не оформляет. Пример — P854BT78, S-0021, цепь ГРМ на ЯМЗ-236М2.
- **Проверка чисел в ответе:** если числа нет на полученных агентом страницах, механик видит предупреждение «не подтверждено руководством».
- **Память по ТС:** история проверок и заявок, предупреждение о повторной заявке.
- **Демо-режим без ключа LLM.**

**Работает на заглушках.** ML-сервис НейроДВС и ТОиР — заглушки заказчика. Их адреса задаются в `.env`, для боевых сервисов код менять не нужно. Данные машин синтетические. Заглушка ТОиР хранит заявки в памяти, поэтому после перезапуска нумерация снова начинается с TKT-0001.

**Не сделано:**
- голосовой ввод и вывод;
- распознавание госномера и фото положения стенда;
- векторный (семантический) поиск — используется BM25 со стеммингом;
- редактирование работ и запчастей в форме: механик меняет приоритет в карточке, остальное просит изменить у агента текстом.

## 2. Подход и архитектура

**Путь запроса.** Механик пишет в веб-чат или нажимает кнопку. Ответ идёт потоком: FastAPI → агентный цикл LLM. В цикле модель сама выбирает один из шести инструментов:
- `get_diagnosis` — Mock ML API НейроДВС;
- `search_manuals` — BM25-поиск по 6 PDF-руководствам; фильтр по модели двигателя из карточки ТС применяется всегда, поэтому норматив другого двигателя в выдачу не попадает;
- `read_manual_page` — дочитать страницу;
- `get_vehicle_history` — `vehicles.json` и сохранённые заявки;
- `prepare_ticket` — черновик заявки;
- `submit_ticket` — Mock ТОиР API.

Ответ модели со ссылками `[[руководство:страница]]` приходит в интерфейс, ссылка открывает текст страницы и PDF.

**Где решает модель:**
- какой инструмент вызвать и как переформулировать поисковый запрос;
- как объяснить результат и какие гипотезы предложить (они помечаются «предположение агента, не из руководства»);
- состав работ и запчастей в черновике заявки.

**Где решает код, а не модель:**
- **Приоритет.** Базовая критичность типа неисправности плюс поправка по anomaly_score: ≥ 0,80 → high, ≥ 0,65 → medium. Механик видит предложенный приоритет и может его изменить.
- **Качество записи.** При `bad` выводов нет. При `warning` нужно подтверждение механика. При уверенности ниже 0,50 заявки нет.
- **Совместимость типа неисправности с двигателем.**

**Как проверяется ответ:**
1. Каждое число с единицей измерения сверяется с текстом страниц, полученных в этом диалоге. Неподтверждённое значение помечается.
2. Ссылка на страницу, которую агент не получал поиском, подсвечивается красным. В заявку сервер такие ссылки не пропускает.
3. Заявка уходит в ТОиР только по кнопке механика.
4. Системная инструкция:
   - запрещает нормативы «из общих знаний»;
   - требует при противоречии источников приводить обе формулировки;
   - разрешает писать запрет выпуска в рейс только при прямом запрете в руководстве.
5. 11 автотестов на правила агента и контрольный прогон из 13 вопросов на живой модели.

## 3. Стек и модели

- **Модель:**
  - основная — Google Gemini `gemini-3.8-flash` через Google AI Studio, облачный OpenAI-совместимый API;
  - резервные — `gemini-3.7-flash` и `gemini-3.5-flash-lite`: при перегрузке (503/429) агент повторяет запрос и переходит на них.
  - Провайдер меняется в `.env`: Claude через Anthropic SDK или любой OpenAI-совместимый API (GigaChat- или YandexGPT-шлюз, vLLM, Ollama).
- **Backend:** Python 3.12, FastAPI, Uvicorn, httpx, Pydantic. Агентный цикл написан без фреймворков.
- **RAG:**
  - PyMuPDF — разбор PDF;
  - Tesseract OCR (rus+eng) — 39 страниц без текстового слоя;
  - rank-bm25 + snowballstemmer (русский) — поиск;
  - индекс — JSONL в репозитории, в памяти процесса.
- **Хранение:** отдельной базы данных нет. Справочник ТС — `vehicles.json`, история заявок — `data/state/tickets.json`.
- **Frontend:** HTML, CSS и JS без фреймворков, SSE-стриминг, мобильная вёрстка.
- **Хостинг стенда:** Hugging Face Spaces, бесплатный, регион вне РФ: Gemini API недоступен с российских IP. Есть Dockerfile и `render.yaml` для Render.

## 4. Расчёт стоимости эксплуатации

https://github.com/alexeyleo13-eng/digital-mechanic/raw/main/docs/cost_calculation.xlsx

- **Сценарий:** диагностика → 2–3 вопроса механика → заявка. На gemini-3.8-flash он стоит ≈ 6,88 ₽ по курсу ЦБ 82,3130 ₽ за $.
- **Разбивка:** разбор 1,86 ₽, вопросы 3,01 ₽, заявка 2,02 ₽.
- **Эмбеддингов нет.** Разовая индексация руководств — 0 ₽.
- **Парк:** 50 ТС, проверка раз в 2 недели. Выходит ≈ 109 сценариев и ≈ 750 ₽ в месяц — это оценка сверху.
- Варианты и допущения — на листе «Пояснения».

## 5. Запуск и поставка

**Состав поставки** (репозиторий):
- `app/` — агент, инструменты, сервер, интерфейс;
- `scripts/` — сборка индекса, загрузка PDF с диска заказчика, запуск всех сервисов, проверка ключа LLM, контрольный прогон;
- `data/index/` — готовый индекс;
- `mock_services/` — заглушки заказчика;
- `tests/`;
- `Dockerfile`, `space_app.py` — для Hugging Face.

**Запуск** (Python 3.10+):
```
pip install -r requirements.txt
cp .env.example .env          # вписать LLM_API_KEY (Google AI Studio)
python -m scripts.run_all     # заглушки ML :8001, ТОиР :8002, приложение :8000
```
Или через Docker: `docker build -t mechanic . && docker run -p 8000:8000 --env-file .env mechanic`.

**Пример запроса** (стенд без логина):
```
curl -N -X POST https://smartleoai-digital-mechanic.hf.space/api/chat \
  -H "Content-Type: application/json" \
  -d '{"vehicle_id":"P456AT178","message":"Какой момент затяжки болтов крышек коренных подшипников?"}'
```

**Ожидаемый ответ.** Поток событий SSE: вызов `search_manuals`, затем текст. В тексте — вертикальные болты крышек коренных подшипников ЯМЗ-236М2 затягиваются моментом **421–461 Н·м (43–47 кгс·м)** со ссылкой `[[yamz236_rk:41]]` (руководство 236.01.01 РК, стр. 41 PDF). Значение 430–470 Н·м из приложения агент поясняет как округлённый пересчёт той же величины.

Тестовый доступ не нужен.
